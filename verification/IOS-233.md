# IOS-233 – iOS background playback via `<audio>` (unverified on a real device)

App-only change on top of 1.0.232. Display typography, `DATA_VERSION`, `yearWord`, offline.js, store.js, and the compact player bar are unchanged. No new SW asset.

- When «פקדים במסך הנעילה» is on and the browser looks like iOS, the local Piper voice plays the same PCM (plus the usual pause pad) through a reused `<audio>` element, as a WAV blob, instead of WebAudio. Media Session still attaches. A silent keep-alive is not started in that path.
- On other browsers the existing WebAudio path is unchanged.
- The setting label, a hint, About, and README state clearly that this has not been verified on a real iPhone. A known residual risk is that iOS may block `audio.play()` on a new `src` when advancing chunks in the background.
- Tests: `tests/piper-audio.test.mjs`.
- External review (agy, Gemini 4 Hydrogen High): SHIP 9.8 first try, harmful_error_count 0.
